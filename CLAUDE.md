# Правила совместной работы над cartium-website

Сайт меняют два человека, каждый в своих ветках и в своих сессиях Claude. Эти правила обязательны
для каждой сессии: они делают так, чтобы конфликт между ветками можно было решить по записям,
а не по памяти.

## 1. Ветки и `main`

- Никогда не вливать ничего в `main` и не пушить в `main`, пока человек явно не попросил об этом
  в чате. Даже после явной просьбы переспросить один раз: «Влить ветку X в main? Сайт на GitHub
  Pages обновится сразу». Делать только после подтверждения.
- Сейчас приоритет по `main` у партнёра. Если в `main` появились его изменения, наша ветка
  подстраивается под них, а не наоборот.
- Каждый работает в своей ветке. Чужую ветку не переписывать (без rebase, amend и force-push),
  только merge-коммиты.

## 2. Каждый коммит говорит, что просил человек

Сообщение коммита пишется так:

```
<Короткий заголовок>

Requested (из чата, слова человека):
- [area] что именно попросили, близко к формулировке человека

Incidental (сделано по ходу, человек об этом не просил):
- [area] что ещё поменялось и почему

Requested-by: <имя или GitHub-логин человека из чата>
Areas: copy, palette, layout, motion, studio, screenshots, pricing, ci, docs
```

- `[area]` из того же списка, что и `Areas`. Изменение без явной просьбы всегда идёт в
  Incidental, даже если оно логично вытекает из задачи (например, переписанные тексты, когда
  человек просил только поменять раскладку).
- Та же запись добавляется в начало `docs/CHANGELOG.md` (новые сверху).

## 3. Как решать конфликты между ветками

Сравнить записи в `docs/CHANGELOG.md` и в сообщениях коммитов обеих веток для каждого
конфликтующего места. Приоритет, от высшего к низшему:

1. **Requested с более точной просьбой.** Если человек прямо просил изменить именно этот
   элемент (этот текст, этот блок, этот цвет), его версия побеждает версию, где элемент
   поменялся как Incidental.
2. **Requested против Requested.** Оба человека прямо просили поменять одно и то же: не решать
   самому. Показать человеку в чате обе версии рядом и спросить, какую оставить.
3. **Incidental против Incidental.** Оставить версию из ветки с приоритетом по `main` (сейчас
   партнёрская) и коротко сообщить человеку, что выбрано.
4. **Факты продукта важнее всего.** Цены, лимиты тарифов, названия функций сверяются с кодом
   продукта (`insomnia.workshop`: `billing/plans.py`, `application/feature_registry.py`,
   `application/store_templates.py`) независимо от того, чья версия.

После решения конфликтов в merge-коммите перечислить каждое спорное место и почему выбрана
та или иная сторона.

## 4. Прочее

- Язык сайта украинский; в текстах без длинных тире, без выдуманных отзывов и цифр.
- Перед пушем: `npx astro check` и `npm run build` без ошибок.
- Бриф и решения по дизайну: `docs/BRIEF.md`. Структура и команды: `README.md`.
